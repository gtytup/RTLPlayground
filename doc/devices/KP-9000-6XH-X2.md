# Keeplink KP-9000-6XH-X2 / KP-9000-6XHML-X2

Following is documentation for switches marked as `KP-9000-6XH-X2` or
`KP-9000-6XHML-X2`.

Using SPI clamp in-board is the only method for initial installation.

### Label specifications

- **Name**: 4X 2.5G RJ45 Port + 2 X 10G SFP+ Port  
- **Model**: KP-9000-6XH-X2 / KP-9000-6XHML-X2
- **Ports**:  
  - 4 × RJ45: 10/100/1000/2500 Mbps  
  - 2 × SFP+: 1000 / 2500 / 10000 Mbps  

### Machine target

These devices exist with different PCB revisions. Select the machine target by
the PCB silkscreen, not by the label on the case. The `6XH` / `6XHML`
distinction appears to be a stock firmware, SKU or label difference, not a
reliable indicator of PCB wiring. The PCB revision defines the hardware layout.

| PCB silkscreen | Known labels / devices | Recommended machine target | Equivalent target | Legacy target |
| --- | --- | --- | --- | --- |
| `2M-PCB43-V1.1` | Mokerlink 2G040210GSM web-managed 4+2 switch | `MACHINE_KP_9000_6XHML_X2_V1_1` | `MACHINE_KP_9000_6XH_X2_V1_1` | `MACHINE_KP_9000_6XHML_X2` |
| `2M-PCB43-V1.1` + 4 MB W25Q32JV | Ganwen `GW-9000-6XH-X2` | `MACHINE_GW_9000_6XH_X2_V1_1` | same V1.1 layout, single-IO flash | - |
| `2M-PCB43-V1.2` | `KP-9000-6XHML-X2` | `MACHINE_KP_9000_6XHML_X2_V1_2` | `MACHINE_KP_9000_6XH_X2_V1_2` | `MACHINE_KP_9000_6XHML_X2` |
| `2M-PCB43-V2.1` | `KP-9000-6XH-X2`, `KP-9000-6XHML-X2` | `MACHINE_KP_9000_6XH_X2_V2_1` or `MACHINE_KP_9000_6XHML_X2_V2_1` | same V2.1 layout | `MACHINE_KP_9000_6XH_X2` |

The V1.1 and V1.2 boards currently use the same V1.x GPIO, SFP, port and LED
layout. The V2.1 board uses a different V2.1 layout with custom LED muxing.
Legacy targets are preserved for compatibility with already-tested devices, but
new builds should prefer the explicit PCB-revision targets.

### What works

- All four 2.5GBASE-T RJ45 ports at 10/100/1000/2500 Mbps
- SFP port with 10G modules 
- LEDs
- untested due to missing Hardware: SFP+ ports equipped with 1G or 2.5G SFPs.

### Ganwen GW-9000-6XH-X2 (2M-PCB43-V1.1 with a 4 MB Winbond W25Q32JV)

The Ganwen GW-9000-6XH-X2 is sold as an unmanaged 4x2.5G + 2x10G SFP+ switch
and uses the same `2M-PCB43-V1.1` board as the Mokerlink 2G040210GSM, but is
fitted with a **4 MB Winbond `W25Q32JVSIQ`** (JEDEC `EF 40 16`).

This flash chip is **not readable in DIO mode** on this board:

- `flash_init(1)` (DIO, `0xBB`, divider 4) makes code fetch return corrupted
  data every few reads. The console shows garbled strings in the middle of a
  line and the CPU occasionally runs off into the weeds, which looks like a
  boot loop. The failing reads are intermittent, a power cycle sometimes boots
  all the way to the prompt and sometimes dies after a few seconds.
- Halving the DIO clock (`SFR_FLASH_CONF_DIV` 4 -> 8) does **not** help, so this
  is not a clock margin problem.
- Setting the mode byte to the `Fxh` that the W25Q32JV datasheet asks for
  (`SFR_FLASH_MODEB` 0x18 -> 0xF0) hangs immediately after
  `Detecting CPU:`, so the controller's DIO MMIO read needs the 0x18 setting.

Use **`MACHINE_GW_9000_6XH_X2_V1_1`**, which selects single-IO (`0x0B`) flash
reads via the `flash_sio` field of the machine description. Only the management
plane is slower, the ASIC keeps forwarding in hardware. Everything was verified
with this target:

- All four 2.5GBASE-T RJ45 ports at 10/100/1000/2500 Mbps, in the right order
- Both SFP+ slots, 10G modules (tested with Finisar `FCBG110SD1C05-1RA`)
- LEDs, web interface, configuration stored in flash

The board is fitted with a 4 MB flash but RTLPlayground only uses the first
1 MB (`FIRMWARE_UPLOAD_START` is 0x80000), so the region above the firmware
image keeps whatever the stock firmware left there. Erase the whole chip when
flashing, otherwise a leftover that starts with `00 40` at 0x80000 is taken for
a staged update image.

Also note that the reset button footprint is unpopulated on this board, which
the firmware notices as a button that is held down, see [Reset Button](#reset-button).

## Reset Button

There's an unpopulated Reset button on the front left side of the PCB.
It can easily be soldered, you'll need an 4.5mmx4.5mm 90° button switch with a 3-pin footprint.
I got mine here: https://de.aliexpress.com/item/1005007295346702.html
The front case has already the hole in the metal case, you just have to punch a hole through the foil.

The pin is left floating while no button is fitted. With the V1.1 layout
(`GPIO54`, `reset_pin`) the firmware then reads it as a button that is held
down, so the boot waits 30 s before it continues
(`[Button held >30s at boot; continuing normal boot]`). Nothing else is
affected: the configuration is untouched, and on this board the pin sits
stably low, so the running system never sees a button event.

So there are two options:

- Solder the button **together with** a 10k pull-up from the reset pin to 3V3.
  Then press-and-hold works as designed: more than 3 s resets the chip,
  10-30 s restores the default configuration. The 30 s wait is gone.
- Leave the footprint empty and accept the 30 s wait at every boot.

## Power supply

Input power is delivered via barell plug, `12V 1A` adapter was provided.
